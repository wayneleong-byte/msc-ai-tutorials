⭐ 主 bot 起步：10 條規則（1–5）

主 bot＝入口／路由／閘／物證。每卡：做什麼 → 為什麼。

🎯
1. 一件事一句職責
做：只當入口與閘，不做所有 domain。
為何：避免雜訊與權限過大。
🌐
2. 繁中／時區／安靜
做：繁中、Asia/Macau；週末／noop 安靜。
為何：減少打擾、時間一致。
📨
3. 外發一律草稿
做：電郵／Slack／發帖先 draft。
為何：人把關，防誤寄。
🧾
4. Status ≠ evidence
做：要截圖／URL／mtime。
為何：不信「已完成」自報。
🔒
5. 密碼不入 chat
做：用 Vault／安全表單。
為何：防洩漏進記憶與記錄。

請細讀這三篇官方指南後，檢查我現有的 Bot 設計（先報告，未經同意勿修改任何 Bot；用繁體書面中文）：

1) 各 Bot 名稱與一句職責

☁️ VM：全部 bot 共用一部雲端機

各 bot 有自己螢幕；檔案／登入共用。持久檔放 /workspace。

🖥️ Your computer（本機）

  • Execution：Ask／Always／Never
  • Route traffic：流量經本機 → 對方見本機 IP
  • 適合：內網、要你地區 IP 的站

☁️ Bot's computer（雲端）

  • Update／Reset／Recover
  • 常見為資料中心 IP（如美國等地）
  • 適合：需該區 IP 的服務情境
只作架構說明
地區 IP 能力不教規避服務條款。請遵守各站條款與當地法律。私人／VPN 位址預設可能被擋，除非組織允許。

🔐 本機控制權限 vs Auto-review

🖥️ 本機 Execution

Ask（預設） Always Never

可跑指令、讀寫本機檔、檔案來回（類 CopyToBox／FromBox）。

🛡️ Auto-review

管雲端機高風險動作；與本機 Execution 分開。

詳見 Approvals。

建議
無明確本機檔案需求 → 選 Never allow。團隊 admin 可設上限；第一次批准卡看清楚選項。

🔐 Vault 與安全習慣

🏦
用 Vault
登入資料／必要密鑰放 Vault，不貼 chat。
🚫
不貼 key
API key、密碼、token 禁止進對話／memory。
🖱️
Take over 登入
2FA／驗證碼由你在螢幕完成。
付款與信用卡
Bot 可能存卡並代付（每次金額卡）。不建議交主要信用卡；每次金額自己看清再批。
共用登入
一 bot 登入某站 → 同雲端機其他 bot 也可能用到該站。
